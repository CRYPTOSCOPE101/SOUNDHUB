# User tests — первые 3 сессии, затем фиксы

Цель: **увидеть, как реальный человек проходит путь без подсказок**, и собрать
дословные формулировки — они станут текстами интерфейса, onboarding и
email-шаблонов. Не добавляем фичи, пока не поправим топ-3 боли из тестов.

## Участники (3 теста)

- **2 mix/master-инженера** — один в основном Ableton, второй не важно в чём.
- **1 клиент/артист, который не работает в DAW** (важно: не-технарь).
- Желательно четвёртым: человек с небольшим лейблом / A&R (если найдётся).

## Задачи — у каждого своя, не весь маршрут всем подряд

| Участник | Задача |
|---|---|
| **Engineer** | Создать session из brief → отправить ссылку → экспортировать requests (MD/CSV) → загрузить новую версию **через CLI** (`./backend/soundhub push …`) |
| **Client / artist** | Открыть public link **с телефона** → оставить structured note + voice note → сравнить две версии → отправить feedback → approve |
| **A&R / label** | Посмотреть version history → выполнить approval **по своей роли** (настроить/использовать approval chain) → проверить delivery package и payment/delivery flow |

## Как проводить

1. **Не объясняй интерфейс заранее.** Вступительная фраза одна:
   > «Представь, что это твой текущий проект. Сделай то, что сделал бы обычно.»
2. Отвечай только наводяще: «посмотри на страницу», «попробуй нажать» — без
   описания шагов.
3. Записывай экран, где участник остановился, и **дословно** его формулировки.

## Что записывать — дословные цитаты

Лови буквально (это готовые тексты для UI/onboarding/email):

- «Я не понял, что это…»
- «Я бы ожидал кнопку здесь…»
- «Мне страшно нажать Approve, потому что…»
- «Я не вижу, что изменилось…»
- «Я бы всё равно отправил это в WhatsApp, потому что…»

## Чек-лист лендинга (показать до/после первого экрана)

1. **«Max for Live panel prototype»** рядом с `WAV, MP3 & stems` — спроси
   не-Ableton пользователя: понятно ли, что уже работает, а что прототип?
2. **Marketplace** — после первого экрана спроси: «Как ты думаешь, для чего
   SoundHub?» Если ответ «магазин пресетов» — marketplace надо опускать ниже.
3. **Roadmap (4 колонки)** — доходят ли люди до него вообще и влияет ли он
   на решение попробовать demo.

## Метрики

| Метрика | Как мерить |
|---|---|
| Time to first feedback | от открытия ссылки до первого комментария/voice note |
| % отправивших consolidated notes | submit round без напоминания |
| Число revision rounds | сколько раундов до approval |
| % approvals без ручных напоминаний | approve без пинга инженера |
| Time-to-payment | от invoice до оплаты checkout |
| Где просили помощи | список экранов/действий |

## После 3 отчётов

1. Свести топ-3 боли по частоте и формулировкам.
2. Точечно поправить: onboarding инженера / публичную review-страницу /
   approval copy / pricing / landing narrative.
3. Только потом: USDC, Max for Live review comments, REAPER.

## Что НЕ тестируем и не строим сейчас

- USDC checkout, mainnet proofs, DAO, NFT-лицензии, расширение marketplace —
  пока реальные пользователи не платят за текущий workflow.

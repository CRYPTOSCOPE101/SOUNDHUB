SoundHub API

Version control and collaboration for music production projects. Manage sessions across Ableton Live, Cubase, REAPER, and FL Studio — with review, comments, approvals, and release delivery.

v0.1.0 REST + JSON OpenAPI 3.1 JWT Bearer Auth

Authentication

Every authenticated request requires a Bearer token in the Authorization header. Tokens are obtained by logging in or registering via the /api/auth/login endpoint.

Shell
# 1. Log in — returns a JWT token
curl -X POST https://soundhub-backend.onrender.com/api/auth/login \
     -H "Content-Type: application/json" \
     -d '{"username": "demo", "password": "demo123"}'

# 2. Use the token in subsequent requests
curl https://soundhub-backend.onrender.com/api/projects \
     -H "Authorization: Bearer eyJhbGciOi..."
ℹ️
Tokens expire after 7 days by default (configurable via SOUNDHUB_TOKEN_EXPIRE_MINUTES). Include the token in the Authorization: Bearer <token> header for all authenticated endpoints.

Wallet Login (EVM)

For Web3-enabled users: request a nonce with your wallet address, sign the message with MetaMask, and verify the signature. This links your on-chain identity to your SoundHub account.

JavaScript
// 1. Get a nonce to sign
const { message } = await fetch('/api/auth/wallet/nonce', {
  method: 'POST',
  body: JSON.stringify({ address: walletAddress })
}).then(r => r.json());

// 2. Sign the message (via MetaMask)
const signature = await signer.signMessage(message);

// 3. Verify and receive a JWT
const { access_token } = await fetch('/api/auth/wallet/login', {
  method: 'POST',
  body: JSON.stringify({ address: walletAddress, message, signature })
}).then(r => r.json());

Base URL

All API endpoints are prefixed with /api. Use the production base URL:

Production
https://soundhub-backend.onrender.com/api

In local development, the frontend dev server proxies /api requests to http://localhost:8000/api automatically.

Auth Endpoints

POST /api/auth/login

Log in with username and password. Returns a JWT access token and user profile.

FieldTypeDescription
usernamestringUsername (required)
passwordstringPassword (required)
POST /api/auth/register

Create a new account. Same payload and response shape as login.

GET /api/auth/me

Get the current authenticated user's profile (bio, specialty, wallet address, etc.).

PATCH /api/auth/me

Update profile fields: bio, specialty, location.

Projects

Projects are version-controlled containers for your music files — similar to Git repositories. Each project has branches, commits, and a file tree.

GET /api/projects

List all projects owned by the authenticated user.

POST /api/projects

Create a new project.

FieldTypeDescription
namestringProject name (required)
descriptionstringShort description
POST /api/projects/{id}/commits

Upload a new commit with files (multipart/form-data). Files are versioned with SHA-256 content addressing.

FieldTypeDescription
messagestringCommit message (required)
branchstringTarget branch (default: main)
filesfile[]One or more project files (.als, .cpr, .rpp, .flp, etc.)
GET /api/projects/{id}/diff

View the file diff between two commits or branches. Returns changed files with content comparison.

Review Sessions

Review sessions are the core collaboration workflow — analogous to Frame.io for video. Upload audio versions, collect timestamped comments, track approvals, and manage revisions across rounds.

POST /api/sessions

Create a new review session (optionally linked to a project).

GET /api/sessions/{id}

Get session details including versions, brief, share settings, and reminder config.

PATCH /api/sessions/{id}/share

Configure share settings: password, expiry, permissions, feedback due date, deposit, and more.

🔗
Every session gets a unique share_token for public review links — no account required for reviewers. Use /api/sessions/public/{token} endpoints for unauthenticated access.

Versions

Each review round can have multiple versions. Upload audio files (WAV, MP3, FLAC, etc.) and track their status through the review lifecycle.

POST /api/sessions/{id}/versions

Upload a new audio version (multipart/form-data). The backend generates waveforms and loudness analysis automatically.

FieldTypeDescription
fileaudioAudio file (required, max 2 GiB)
messagestringVersion notes / changelog
POST /api/sessions/{id}/versions/{vId}/status

Set version status: in_review, approved, changes_requested, replaced.

Comments

Timestamped comments are the primary review mechanism. Leave feedback at specific points in the audio, with optional voice messages and threaded replies.

POST /api/sessions/{id}/versions/{vId}/comments

Add a timestamped comment (or reply to an existing comment via parent_id).

FieldTypeDescription
time_snumberTimestamp in seconds (required)
bodystringComment text (required)
parent_idintParent comment ID for threaded replies
POST /api/sessions/{id}/versions/{vId}/comments/voice

Record a voice comment — upload an audio file (OGG, M4A, WebM, MP3) alongside the text.

PATCH /api/sessions/{id}/versions/{vId}/comments/{cId}

Resolve or unresolve a comment: ?resolved=true.

Approvals

Track formal approvals with scope, status, and notes. Supports multi-reviewer approval chains.

POST /api/sessions/{id}/versions/{vId}/approvals

Submit an approval or rejection for a specific scope (e.g., "mix", "master", "arrangement").

FieldTypeDescription
scopestringApproval scope (e.g., "mix", "master")
approvedbooleantrue = approved, false = rejected
notestringOptional note from approver
approver_namestringDisplay name of the approver

Reference Tracks

Compare your mix against reference tracks side-by-side. Upload references or link to external URLs, then run A/B comparison with level matching.

POST /api/sessions/{id}/references

Add a reference track from an external URL (SoundCloud, YouTube, etc.).

POST /api/sessions/{id}/references/compare

Run an A/B comparison between a version and a reference track, with automatic LUFS level matching.

Release Packages

Final delivery packages bundle the approved version with deliverables (master, stems, artwork, metadata) and generate a verified release manifest.

POST /api/release-packages

Create a release package from an approved version, with a template for required deliverables.

POST /api/release-packages/{id}/preflight

Run preflight checks: verify audio levels, file formats, required deliverables completeness.

POST /api/release-packages/{id}/lock

Lock the package — generates an immutable release manifest with SHA-256 hash for audit trail.

Checkout & Payments

SoundHub supports both fiat (Stripe) and crypto (USDC on Base) payments for deposits, extra review rounds, and release packages.

POST /api/sessions/{id}/checkout

Create a Stripe checkout session for a deposit or extra review round payment.

POST /api/release-packages/{id}/checkout/usdc

Generate a USDC payment request for Base chain — returns a payable address and amount.

⚠️
Test mode: Stripe and USDC payments require API keys. Without STRIPE_SECRET_KEY configured, checkout endpoints return manual-invoice mode. See Interactive API for details.

Assets (Marketplace)

The catalog hosts user-uploaded music assets — presets, samples, loops, and project templates. Browse, preview, and download licensed assets.

GET /api/assets

Browse the catalog. Supports filtering by genre, bpm_min, bpm_max, format, and plugins.

GET /api/assets/{id}/preview

Stream a preview of the asset (audio file).

POST /api/assets/{id}/receipt

Generate a license receipt for a purchased asset (used by the CLI and VST3 agent).

Search

GET /api/search?q={query}

Full-text search across projects, sessions, and assets. Returns grouped results.

Public Portfolio

Every engineer has a public portfolio page showcasing their approved review versions — visible to clients and the public.

GET /api/portfolio/{username}

Public portfolio for a user: bio, approved versions, and links to session reviews.

Reminders & Notifications

Automated email reminders for review sessions — configurable per session (review due, invoice due, feedback follow-up).

POST /api/reminders/evaluate

Trigger the reminder evaluation engine — scans pending reviews and sends due notifications via SMTP.

PATCH /api/sessions/{id}/reminders

Update reminder settings: enable/disable review reminders, set due dates, configure email recipients.

Error Handling

The API uses standard HTTP status codes. Error responses always include a detail field:

Error Response
{
  "detail": "Invalid username or password"
}
StatusMeaning
200Success
201Created
204No Content (e.g., successful DELETE)
400Bad Request — invalid payload or missing fields
401Unauthorized — missing or invalid token
403Forbidden — insufficient permissions
404Not Found — resource does not exist
422Validation Error — field type mismatch
500Internal Server Error
